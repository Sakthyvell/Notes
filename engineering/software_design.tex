\section{Software Design}

There seems to be a lot of buzzwords, techniques and methodologies around software design. Everything works but it gets tiring after a while to keep up with all these things. \cite{hunt2000pragmatic} presented "ETC" - Easy to change as the fundamental goal of software design. Let's face the reality - whatever you build, it's going to be break one day. New requirements will come up, bugs will be found, technologies will evolve. So it makes sense to design it in a way that it is easy to change. Simple. Any principles that helps you achieve that is worth considering.
